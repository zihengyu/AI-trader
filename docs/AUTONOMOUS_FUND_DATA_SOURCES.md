# AI 模拟基金：数据源与升级路线

本应用用到的每个数据源、它们的局限，以及 Yahoo 不够用时可以接入什么。

**Last Updated:** 2026-11-14

**Status:** 免费数据源已接入并有离线测试；真实网络访问需在部署服务器上用 `check` 验证

**Audience:** 运营者，以及为 `scripts/autonomous_fund/` 增加数据源的贡献者

## Overview

专业量化和这套系统的最大差距之一在数据：点时（point-in-time）基本面、包含已退市公司的历史、
有服务等级保障的行情、事件日历。本文说明现在用什么、各自的边界，以及按成本从低到高的升级选项。
新增数据源必须遵守仓库的第一条规则：**缺数据就空着，绝不编造、补齐或沿用旧价格**（见 `docs/BACKTESTING_ARCHITECTURE.md`）。
所有数据源都接在本应用里，不修改 LumiBot 核心。

## 现在用的数据源

| 数据 | 来源 | 用途 | 局限 |
|---|---|---|---|
| 实时报价、分钟线、日线（local 模式） | Yahoo（非官方接口，推送＋下载） | 本地撮合、风控历史、因子 | 没有服务保障，会限流；大陆服务器通常无法访问；不含已退市股票 |
| 行情与成交（paper 模式） | Alpaca Paper | 券商撮合、账户 | 免费账户的实时行情来自单一交易所（IEX），历史 SIP 数据有 15 分钟延迟限制 |
| 日线备用源与交叉核对（local 模式） | Alpaca 历史行情 API | Yahoo 失败时的风控和因子历史（`risk_history_fallback`）；每天逐只核对 Yahoo 日线（`bar_quality`） | 需要 Alpaca Key；免费账户只有 IEX 数据，收盘价与全市场收盘价有几个基点差别，只能发现明显错误；本地撮合和分红拆股仍用 Yahoo |
| 公司行动交叉核对（local 模式） | Yahoo 和 [Alpaca Corporate Actions](https://docs.alpaca.markets/us/reference/corporateactions-1) | 覆盖请求和缓存日线历史的拆股、美元现金分红及分拆证据，使用数据员或 `prefetch` 发布的判定 | Alpaca 可能晚报，单边记录标为未确认；分拆派股比例不等于价格调整系数；不用于自动更正账本 |
| 标普 500 成分加入日期 | github.com/datasets 发布的标普 500 成分 CSV（维基百科列表的镜像，公有领域） | 历史因子检验里一只股票从加入指数那天才计入 | 社区维护；只有现在的成分股，已移出的不在其中；每 30 天刷新一次 |
| 标普 500 加入和移出区间 | [社区历史成分表](https://github.com/lawcal/sp500-components-history) | 给已有行情的证券补充加入、移出和重新加入区间 | 从 2007 年 3 月开始覆盖；跳过估算日期、无法区分发行人的代码和与当前名单不一致的区间 |
| 场外卖空成交占比 | [FINRA Consolidated NMS 日文件](https://www.finra.org/finra-data/browse-catalog/short-sale-volume-data/daily-short-sale-volume-files) | 因子偏好组与回避组的拥挤度参考，数据员在 local 或 paper 模式下收集 | 无需密钥；卖空量已含豁免卖空，分母只包含 FINRA 报告的成交。不是空头持仓，也不代表交易所成交 |
| 财报基本面 | SEC EDGAR XBRL company facts | 因子实验室的盈利、营收、毛利、经营现金流、净资产、总资产、股本 | 只有美国上市公司；按 `filed` 日期做点时；多类别股的股数为空；需要 `FUND_SEC_USER_AGENT` |
| 8-K 公告、新闻 | SEC、Yahoo、Google News、美联储 RSS | AI 的资讯上下文 | 标题级信息，不保证完整；内容按不可信数据处理 |
| 宏观环境 | FRED | 美债收益率、曲线、高收益债利差、VIX | 市场类序列不修订，可用于回测；经济数据（如 CPI）有修订，本应用没有使用 |
| 财报日历 | Finnhub（有 Key 时）或 Yahoo 日历 | 财报前降仓 | 日期偶有变动；拿不到不猜测；只在 local／paper 生效 |
| 经济日历 | FRED 发布日历（`releases/dates`，需要 `FRED_API_KEY`） | 数据员整理未来三周 CPI、非农、GDP、PCE、PPI、零售、初请、FOMC 等公布日期 | 只有日期没有具体时刻；按发布名称筛选，FRED 改名会漏掉，需要时补充名单 |
| 盘前行情、全球市场 | Yahoo（含盘前盘后的分钟线；股指期货、VIX、10 年期收益率、美元指数、欧元、日元、原油、黄金、日经、恒生、欧洲斯托克 50） | 数据员给盘前研究和盘中决策的背景 | 非官方接口；盘前成交稀少；期货和外汇的“涨跌”是相对上一个纽约日的最后一根 K 线 |

`check` 命令会逐项探测这些服务能否连通（见 `docs/AUTONOMOUS_FUND_UBUNTU.md`）。

本地报价先用新鲜推送，再检查同一 Yahoo 分钟响应中的最新成交价和源时间（`regularMarketPrice`／`regularMarketTime`），
最后才回退已完成分钟线。最新成交元数据也须满足当前常规时段与源时间新鲜度要求，不采用正在形成的分钟线收盘价。
当前分钟内的合格推送比任何已完成分钟线都新，可直接返回，不先等待历史下载；它不附加编造的分钟成交量，
本地撮合仍独立读取提交之后完成的分钟线。较早分钟的推送仍与历史数据比较，过期和未来时间戳仍拒绝。
`price_kind=chart_last_trade_with_spread_proxy` 和 `quotes_by_kind.chart_quote` 标识这种回退；不补造分钟成交量，
模拟撮合仍要求提交后新完成的分钟线。数据源未提供合格报价时仍会等待，不能保证每个符号都有实时数据。

价位提醒的报价失败会在账户账本元数据 `price_alert_health` 中保留首次／最近失败时间、实际失败检查次数及
最近一次拒绝原因和源时间，不受 30 分钟通知去重影响。下一次取得有效报价时，原子记录 `price_alert_recovered`
通知并清除该次失败状态，重启后也可继续识别恢复；恢复不要求价位已经越线，不补认间隙里的价格触发。
`bash scripts/fund-logs.sh status` 显示尚无恢复证据的活动提醒，`errors` 同时保留失败和恢复记录。
这些是离散检查的证据，不是连续行情覆盖率；移除提醒只清理状态，不伪报恢复。旧版本没有计数的检查不追补。
被拒报价的诊断还保留该次读取的推送开关、推送和图表成交源时间，区分未观察到推送与图表成交已过期；
后续其他读取不会覆盖这次报价自带的源时间证据，不输出原始供应商响应。
`bash scripts/fund-logs.sh quotes [SYMBOL]` 可离线查看这些证据，分别标明最近报价快照与最近拒绝记录的时间；
缺失／过期快照和无法核实的源时间保持未知，不触发新行情请求或改变提醒状态。Telegram 状态查询也显示活动提醒故障。

Alpaca 备用日线要求源时间戳带明确时区，再按纽约日期筛选已完成交易日；不会把缺少时区的时间按服务器位置解释。
被采用的收盘价必须为有限正数，无效响应会单独报告该证券历史不可用，其他证券仍独立读取。
FRED 的无效数值不进入宏观摘要；运行进程的可选磁盘缓存失败时，已经获取的有效观测仍保留在当天的内存中。
日缓存先写完整的临时文件，再原子替换。Windows 若暂时锁住目标文件，程序会短暂重试，持续失败时保留上一份完整缓存。

**日线交叉核对**（`bar_quality.py`）：local 模式配了 Alpaca Key 时，数据员每小时下载日线后，逐只把 Yahoo 的完成日线
与 Alpaca 的拆股及分拆调整日线比较（`adjustment=split,spin-off`，不含现金分红复权；
交易进程对还没核对的证券自己核对一次），结果按证券按天缓存在 `cache/daily/<日期>/quality/`。
这个口径也用于 Yahoo 失败时的备用历史；不会直接改为包含现金分红的 `all`，避免混淆独立的分红核算。
旧版 split-only 判定在下次核对时重算，无需删除共享缓存。参考源故障期间，相同行情与截止日期已记录的拒绝仍保留；
恢复后按新口径再核对。一致后记录恢复事件，报告不再沿用该证券先前的失败结论。
两边都不被默认是对的：

- 某个交易日收盘价相差超过 2%：这一天的数据剔除，不用另一边的值替换，也不插值；
- 相差的交易日超过比较天数的 5%（至少 5 天，通常是一边漏了拆股调整），或最新一个完成交易日就有分歧：这只证券当天停用，
  风控把它当作没有历史（不新增买入），因子检验和股票池快照里也没有它，市场快照里列在 `no_history`；
- 共同交易日不足 20 个不下结论。若 Alpaca 已提供较新的完成日线而 Yahoo 仍缺失，盘后会列出相应证券和日期。
  核对只报告缺口，保留 Yahoo 现有的有效记录；
- Alpaca 连不上时暂停新的核对 10 分钟。相同行情和截止日期已有判定的继续执行；其余暂用未核对数据，恢复后在下次读取时重试。
  Yahoo 读取失败或没有有效收盘价而直接使用 Alpaca 时，记为备用源，不会用 Alpaca 核对自身。

收盘后有一条通知（`bar_quality_issues`），列出停用和剔除了交易日的证券，附例子。
例子中的百分比是同一历史日两个数据源的价差，不是该证券当天的涨跌幅。paper 模式用券商自己的数据，不核对。

公司行动按除权日配对。拆股比例相差超过 0.01%，或还原为除权日股数口径后每股分红差超过半美分和 1% 中的较大者，
当天从风控历史、因子和记分卡中停用该证券。单一数据源返回的行动和无法确认计价口径的分红单独列为未确认。
核对起点至少覆盖请求长度对应的日历跨度及实际缓存中的最早日线，并保留最低 120 天范围；扩大历史请求时旧判定也重算。
Alpaca 分拆记录保存母公司、子公司及派发比例，不把派股比例当成价格系数或普通拆股比例。
同日 Yahoo 的合成价格调整与真实股数转换可能不可直接比较；该日拆股及分拆前现金分红的股数口径列为未确认，
价格仍须通过上述日线核对。无关日期的拆股／分红矛盾、真实坏价和缺行情仍按原规则处理。
这些证据不授权自动派发子公司股票、分配成本或修改旧账本，复杂公司行动的持仓核算仍需独立验证。
“待核对”不是“已错账”；提供方可能晚报，也不能把缺少同日记录解释成没有发生公司行动。

宏观摘要的 `regime.yield_curve_comparisons` 只对同一观察日期的 FRED 收益率计算长端减短端，单位为百分点，
负值才是倒挂；日期不一致时保持不可用，原有宏观交易约束不变。研究提示要求注明期限、来源和观察时间，
不能把盘中收益率代理与旧官方值拼成同一时点曲线。经济日历只有日期，模型需按事件分别核对发布机构的准确日期、
时区和结果；数据台缺标题只说明采集缺项。以上均无需新增付费数据源。

## Yahoo 的问题和对策

1. **不稳定、会限流**：已有对策——每个证券每天只下载一次日线、单飞请求、失败退避、Alpaca 日线备用源。
   限流时风控把缺历史的证券视为“不能加仓”，不会用旧数据下单。
2. **大陆服务器访问不了**：把服务器放在境外地域，或设置 `HTTPS_PROXY`。
3. **没有已退市股票**：研究股票池是“今天的大盘股”，因子回测有幸存者偏差（会高估动量、低估风险）。
   每日股票池快照保留部分离开股票池的历史，因子先待样本外确认，标普 500 成分股按加入日期计入。
   这些措施能缓解偏差；仍缺退市最终收益、部分基本面和快照开始前的完整成员历史。
4. **数据错误**：偶尔有错误的收盘价、漏掉的拆股调整或缺失的交易日。有 Alpaca Key 时每天交叉核对（见上），
   有分歧的交易日剔除，严重时停用该证券当天的数据。
5. **不是点时数据**：Yahoo 的基本面是最新值，用于历史会有前视。本应用的基本面只用 SEC，不用 Yahoo。

## 升级选项（按成本从低到高）

| 选项 | 解决什么 | 接入方式 |
|---|---|---|
| Finnhub 免费 Key | 更可靠的财报日历 | 已接入：在 `.env` 设 `FINNHUB_API_KEY` |
| FRED 免费 Key | 官方 API，限额更高；经济日历必需 | 已接入：设 `FRED_API_KEY` |
| Alpaca 付费行情订阅（SIP 实时） | 全市场实时报价、无延迟历史 | paper 模式直接受益；local 模式的实时报价仍用 Yahoo，需要新增报价适配器 |
| Polygon.io 股票订阅 | 有服务保障的实时和历史 SIP 行情、拆股分红、参考数据 | LumiBot 已有 Polygon 回测数据源；local 模式需要新增报价和日线适配器 |
| Tiingo | 便宜的日线和基本面 | 可作为日线备用源，按 `history.py` 的接口实现 |
| Sharadar（Nasdaq Data Link）核心美股基本面与价格 | **点时基本面＋包含已退市公司的历史**，消除幸存者偏差，是个人量化常用的专业数据 | 在 `fundamentals.py` 旁实现同样的 `panels(symbols, index)` 接口；研究股票池可改为历史成分 |
| DataBento、ThetaData | 机构级逐笔／分钟数据；ThetaData 还有期权 | LumiBot 已支持回测（ThetaData 只走 Data Downloader，规则见 `AGENTS.md`）；本应用目前不交易期权 |
| 分析师一致预期（I/B/E/S、FactSet 等） | 盈利意外、预期修正类因子 | 价格昂贵，需要单独授权和合同 |

**建议顺序**：
1. 现在（免费）：Yahoo＋Alpaca 备用日线＋SEC＋FRED＋Finnhub 免费 Key。只要部署在能访问这些服务的地域，已能运行全部功能。
2. 想让因子研究更可信：Sharadar 一类含退市的点时数据库（解决幸存者偏差），再把研究股票池扩大到几百只。
3. 想让行情更可靠：Alpaca 付费 SIP 或 Polygon，并为 local 模式实现对应的报价适配器。
4. 将来接 Schwab 实盘（需要你单独明确授权）：报价和成交以券商为准，其余数据源不变。

## 为本应用增加数据源的规则

- 每个源实现成独立模块，可注入 HTTP 客户端，测试只用合成数据，不访问网络；`check` 增加对应探测。
- 历史数据必须标明可得时间：行情只用已完成的 K 线；基本面只用受理日期早于当天的报告；事件日历在回测中不使用当天才知道的版本。
- 失败时返回“不可用”并记录事件，绝不补数、插值或沿用旧值；风控把缺数据视为不能加仓。
- Key 只从 `.env` 读取，输出和日志里不出现 Key 或带 Key 的 URL；新变量同时写进 `.env.example`、`settings.py`、
  `docs/ENV_VARS.md` 和 `docsrc/environment_variables.rst`。
